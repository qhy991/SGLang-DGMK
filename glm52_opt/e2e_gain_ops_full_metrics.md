## 1. 测了什么 / 没测什么

| 场景名 | 实际含义 |
|--------|----------|
| `decode_kv` / 64k bs16·32 | **全新请求**，prompt≈65536，并发 16/32；TTFT≈整段 64k prefill 到首字；**不是**「KV 已是 64k 后再出首字」 |
| `e2e_seq` / 1024·2048·4096 | **全新请求**，prompt 就是该长度，并发 16；**不是**「在 64k cache 上再增量 prefill」 |

| config | 含义 |
|--------|------|

## 3. 指标定义

| 指标 | 含义 | 越大/越小更好 |
|------|------|----------------|
| TTFT p50 / mean (s) | 发请求→首个输出 token | 越小越好 |
| TPOT p50 / mean (ms) | 首字后平均每 token 间隔（decode） | 越小越好 |
| per_req decode tok/s | 单请求 decode 吞吐 ≈1000/TPOT | 越大越好 |
| agg decode tok/s | 本波生成 token 总数 / 墙钟（**含 TTFT**） | 越大越好；长上下文会被 prefill 稀释 |
| wall_s | 本波全部请求结束墙钟 | 越小越好 |
| prompt / completion tokens | 实际 prompt 与生成长度 | 校验用 |
| ×opt0 | 相对同场景 OPT0 的比值 | TTFT/TPOT/wall：<1 更好；tok/s：>1 更好 |

## 6. 结论摘要

- 短/中上下文（1024/2048/4096）e2e：**TPOT 基本打平**（约 ±1–3%）；TTFT 仅在 2048 上略好（约 0.91–0.93×），1024/4096 无稳定收益，`all_gain@1024` TTFT 明显变差（约 1.18×）。
- 64k：TTFT 几乎全是 prefill（~111–115s），配置间差异很小；**decode 看 TPOT**：bs16 无收益或更差，bs32 TPOT 约 0.87–0.88×（样本少，需谨慎解读）。
- `all_gain` 未稳定优于单算子；先前微基准 HIT 未转化为稳定 e2e 收益。
